## 图片分析"报错"修复（vision 图片理解）
- 根因：不是异常。图片能上传能落库，但**整条链路没有代码读它**；`should_answer_general` 把"分析这个图片"判成 general，模型只看到文件名，于是自己编了句"当前只接收文本和数据表名"——半真半假且无下一步。
- 新增 `app/services/vision.py`：视觉模型 `deepseek-v4-flash-vision-exp`（DeepSeek 2026-08 上线），OpenAI 兼容 content 块数组 + base64 data URL；`VISION_BASE_URL`/`VISION_API_KEY_REF` 留空即复用 LLM 注册表默认项；`VISION_ENABLED=false` 一键关。
- 关键设计：**解析失败不调模型**，由 `image_fallback_text` 按五类原因（未配置/不支持/超限/非有效图片/调用失败）给出确切说明 + 替代方案（表格截图导 CSV）。让模型自由发挥正是这次事故的成因。
- 格式按**魔数**判（`sniff_image_mime`），不信扩展名；`is_image_entry` 兼容 mime。
- 接入：routes_chat 在 START 后调 `vision.describe`，发 `VISION` 节点事件（前端 NODE_LABELS 加"识别图片"）并写入 `ctx.image_notes`；generator 把描述拼到 prompt 末尾并标注"不是数仓数据、不得当作查询结果"；general 走 `SYSTEM_IMAGE`（新增第④条：界面截图不要复述图中的对话）。
- 结果事件回传 `image_notes`，前端 evidence 面板展示识别原文（否则识别错了用户无从判断）。
- 踩坑：`_sanitize_attachments` 返回的是 `_public` 视图（无 stored_name），`content_of` 直接读会失败 → describe 必须按 file_id 重新 `file_store.get()`；已在 `content_of` docstring 标注契约。
- 真实调通：用用户 Key 调用 2 次，截图识别准确（含导航项、会话列表、那条错误回复原文）。端到端 TestClient 验证：NODE VISION「1/1 张已识别」→ summary 为真实描述。关闭 VISION 后返回「当前没有配置视觉模型…导 CSV」且不调模型。
