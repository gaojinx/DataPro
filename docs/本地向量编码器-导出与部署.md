# 本地向量编码器：导出与部署

> 适用场景：元数据（表名、字段名、口径定义）不允许发给第三方 embedding 服务，必须在本机/内网完成向量化。
> 代价：生产镜像增大约 1 GB，且需要一次性的模型导出流程。能用 API embedding 就不要走这条路。

## 1. 两套依赖，别混在一起

| 阶段 | 在哪跑 | 依赖 | 体积 |
|---|---|---|---|
| **转换**（一次） | 开发机 / CI（可联网） | `torch`(CPU) + `optimum-intel` + `optimum` + `openvino` + `transformers` | 数 GB，不进镜像 |
| **运行**（每次启动） | 生产容器 | `openvino` + `transformers` + `numpy`（见 `requirements-local-encoder.txt`） | 约 300 MB~1 GB |

生产环境**不需要 torch**。把 torch 打进运行镜像是这条路上最常见的浪费。

## 2. 导出（联网机器执行一次）

```bash
cd datapro

# 转换依赖（CPU 版 torch 足够）
pip install torch --index-url https://download.pytorch.org/whl/cpu
pip install "optimum-intel>=1.20" "optimum>=1.20" "openvino>=2024.4" "transformers>=4.40"

# 导出 + 自检
python -m importer.export_encoder
# 自定义模型 / 池化方式：
# python -m importer.export_encoder --model BAAI/bge-small-zh-v1.5 --out models/bge-small-zh-ov --pooling cls
```

脚本会做四件事：导出 IR、保存 tokenizer、用 OpenVINO Runtime 重新加载跑一句、打印配置片段。
期望输出类似：

```
导出 BAAI/bge-small-zh-v1.5 → models/bge-small-zh-ov
IR 输出 shape=(1, 12, 512)（3 维），输入=['input_ids', 'attention_mask', 'token_type_ids']
池化方式=cls → 句向量维度=512，L2 范数=1.0000
产物：models/bge-small-zh-ov（xxx MB）

配置（写入 .env，或改为容器内的绝对路径）：
  VECTOR_ENCODER=local
  VECTOR_IR_PATH=models/bge-small-zh-ov/openvino_model.xml
  VECTOR_TOKENIZER=models/bge-small-zh-ov
  VECTOR_POOLING=cls
```

实际维度、输入名、输出形状以你的运行结果为准，不要照抄上面的数字。

如果脚本报错，它会打印官方 CLI 的等价命令，可直接复制执行：

```bash
optimum-cli export openvino --model BAAI/bge-small-zh-v1.5 --task feature-extraction --weight-format fp32 models/bge-small-zh-ov
```

## 3. 离线搬运

内网机器拿不到 HuggingFace 时，在联网机器先下载模型目录，再整体拷贝：

```bash
# 命名以 huggingface_hub 版本文档为准（旧版命令为 huggingface-cli）
hf download BAAI/bge-small-zh-v1.5 --local-dir models/bge-small-zh-hf

# 用本地目录导出
python -m importer.export_encoder --model models/bge-small-zh-hf --out models/bge-small-zh-ov
```

**关键点**：`VECTOR_TOKENIZER` 必须指向**本地目录**。如果留着默认的 `BAAI/bge-small-zh-v1.5`，启动时 `AutoTokenizer.from_pretrained` 会去连 HuggingFace，内网会卡到超时——而 `load_local_encoder` 只能报「加载失败」，看不出是网络问题。

## 4. 生产配置

`datapro/models/` 已加入 `.gitignore`，模型产物走制品库或挂载卷，不要进 git。

```dotenv
VECTOR_RECALL_ENABLED=true
VECTOR_ENCODER=local
VECTOR_IR_PATH=/app/models/bge-small-zh-ov/openvino_model.xml
VECTOR_TOKENIZER=/app/models/bge-small-zh-ov
VECTOR_POOLING=cls
VECTOR_MAX_LENGTH=128
VECTOR_CACHE_ENABLED=true
```

Dockerfile 片段（默认镜像不含这些，需要时再加）：

```dockerfile
COPY requirements-local-encoder.txt ./
RUN pip install --no-cache-dir -r requirements-local-encoder.txt
COPY models/bge-small-zh-ov /app/models/bge-small-zh-ov
```

## 5. 预热与验证

```bash
# 编码表/口径/字段并写 meta_embedding 缓存；--prune 顺带清理已下线表的残留向量
python -m importer.warm_vectors --prune
```

期望输出：`预热完成：{'table': 11, 'caliber': 14, 'column': 80}（x.xx s，encoder=local）`。
条数以你的元数据为准。

服务启动后验证：

```bash
# 1) 看日志有没有「向量召回预热完成」；2) 用真实问题观察召回
python - <<'PY'
import asyncio
from app.config import settings
from app.services import recall as R

async def main():
    settings.vector_recall_enabled = True
    r = await R.recall_service.recall("退货的情况怎么样")
    print([(t["table_name"], t.get("vector_score")) for t in r.tables])
asyncio.run(main())
PY
```

关键指标：`vector_score` 出现在结果里 = 向量路生效；全是 `None` = 仍在走纯关键词（看日志里的 `向量召回关闭` / `超时`）。

## 6. 常见问题

| 现象 | 原因 | 处理 |
|---|---|---|
| 日志「未安装 openvino/transformers」 | 运行镜像没装运行依赖 | `pip install -r requirements-local-encoder.txt` |
| 日志「本地编码器加载失败」 | IR 路径错 / IR 与 openvino 版本不兼容 / tokenizer 目录不存在 | 重跑 `export_encoder`，确认两个路径都指向产物目录 |
| 启动卡很久然后关闭向量路 | `VECTOR_TOKENIZER` 指向 HF id 且无外网 | 改成本地目录 |
| 句向量全 0 或相似度全接近 1 | 池化方式与模型不匹配（CLS vs mean），或模型输出是 2 维句向量 | 换 `VECTOR_POOLING`；`export_encoder` 自检会直接报「句向量全 0」 |
| 换模型后召回明显变差 | 旧向量还在 `meta_embedding` 里 | 模型名参与缓存键，不会复用旧向量；但 `kb_chunk`（文档库）需要 `POST /docs/{id}/reindex` |
| 想要更小/更快 | 未量化 | 用 `--weight-format int8` 走官方 CLI 量化（需校准数据，效果需自行评估） |

## 7. 回滚

三层，从轻到重：

1. `RECALL_DEGRADED_MODE=force_keyword` —— 立刻退回纯关键词，不用重启配置中心、不改代码；
2. `VECTOR_RECALL_ENABLED=false` —— 整体关闭向量路（重启生效）；
3. 卸载 `requirements-local-encoder.txt` 并删除模型目录 —— 镜像回到 API embedding 版本。

回滚都不会影响取数主链路：向量路只是召回补位，关掉后退回关键词召回，行为与引入前的版本一致。
