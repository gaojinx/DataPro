## 1. 评审总览

**一句话结论：18 条里 15 条可做、2 条必须先拍板或拆依赖、1 条（X-A01）不算小功能应单独立项；产品经理「旧缺口都已落地」的核心判断成立，但其中多条是降级版，且三条待确认问题里两条的源码事实与清单预设不符。**

**与产品 Top10 的三处关键分歧（理由见 §3/§6）**：

1. **X-R06 不是「需少量后端」**——后端已硬帽 200 行（`executor.py:154`、`config.py:26`、`validator.py:91-94`），对话内结果最多 200 行，纯前端分页即可，后端 offset/limit 反而要绕过校验器与只读账号，**不建议做**。

## 4. 三项待确认的技术答复 + X-A01 裁决

### 4.1 待确认 ①：输入是否有真实字数上限？→ **没有。清单的「N / 上限」形态不成立**

| 检查点 | 结果 | 证据 |
|---|---|---|
| 后端请求模型 | `message: str`，**无** `Field(max_length=…)` | `routes_chat.py:36-39` |
| 后端配置 | 无 message/input 字数配置（仅有 `exec_row_limit`、`rate_limit_per_minute`、`vector_max_length` 等） | `config.py` 全文 |
| 网关 | 未设 `client_max_body_size`，仅走 nginx 默认请求体上限（约 1MB，且是 body 级非字段级） | `nginx.conf:8-19` |
| 前端 | textarea 无 `maxlength` | `App.vue:2638-2640` |

**拍板（技术上可定）**：不虚构上限。X-I03 二选一——(a) 纯计数、不显示分母；(b) 若产品/用户愿意定义一个**建议长度**（如 1000 字），UI 标注「建议 1000 字以内，超出可能影响回答质量」，仍不硬截断。**需要用户拍板的只有「是否引入一个建议数值」**；若同时要硬上限，则必须后端 + 前端联动（返回 422），不再属于小功能。

### 4.2 待确认 ②：时间戳要服务端权威还是 Date.now()？→ **建议 Date.now() 即可，权威时间已在 DB**

| 检查点 | 结果 | 证据 |
|---|---|---|
| 前端 message 结构 | 无 `ts`，push 不写时间；只有会话级 ts | `App.vue:72`、`:557`/`:559`、`:2194`（`fmtTime(s.ts)`） |
| SSE 事件 | 无 `ts` 字段（START 只有 `session_id`/`trace_id`） | `routes_chat.py:110`、`:137-152`（result 事件字段） |
| 服务端权威时间 | **已有**：`message.created_at`、`query_record.created_at`（`server_default=func.now()`），每轮异步落库 | `models.py:37`、`:64`；`routes_chat.py:103-104`、`:178-179` |

**拍板（技术上可定）**：X-C01 保持纯前端——push 时写 `ts: Date.now()`，显示 `HH:mm`，tooltip 完整日期；审计与对话记录继续以服务端 `created_at` 为准，前端明确标注「本地时间」。**只有当用户坚持「界面时间必须与审计逐秒一致」时**，才在 result 事件补 `ts`（小后端，S 档）——这不是当前「回溯有参照」诉求的必要条件。

### 4.3 待确认 ③：千分位能否对字符串型数字执行？→ **不能。wire 上 DECIMAL 金额与编码字符串无法区分**

| 检查点 | 结果 | 证据 |
|---|---|---|
| 执行结果类型 | `columns = list(result.keys())`，`rows = [dict(zip(columns, r))…]`，值为 pymysql 原生类型（int/float/**Decimal**/str/date） | `executor.py:153-154` |
| SSE 序列化 | `json.dumps(event, ensure_ascii=False, default=str)`——**Decimal 与 date 被转成字符串**，int/float 保持 number | `routes_chat.py:46-47` |
| 脱敏 | 只处理字符串值，数值列不改 | `masking.py:74-121`（`:108` `not isinstance(val, str)` 跳过） |
| 后果 | 金额 `72470.55`（DECIMAL）到前端是 **string**；`order_no`/`trade_no` 也是 string，前端无从区分 | 同上 |

**拍板（技术上可定）**：**禁止**对字符串型值做启发式千分位（会把订单号 `202611220001` 变成 `202,611,220,001`，改坏语义，触碰「不改数值/编码」约束）。两种可选实现：
- **纯前端降级**：只格式化 `typeof v === 'number'` 的列（INT/FLOAT 生效），**金额列（DECIMAL）不会生效**——必须向用户说明这一限制；
- **推荐做法**：后端在 result 事件附 `numeric_columns: list[str]`（在 `default=str` 之前按 `isinstance(v, (int, float, Decimal))` 推断列类型），前端按列名白名单格式化，display-only。工作量 S（小后端 + 前端）。

**需要用户拍板**：接受「只格式化 number 列」的降级，还是为金额列投入少量后端（推荐后者）。

### 4.4 X-A01 裁决：**不算小功能，需单独立项**

| 检查点 | 结果 | 证据 |
|---|---|---|
| 字阶变量 | **存在** 10 个 `--fs-*` 变量（2xs…display），但值为固定 px | `style.css:14-24` |
| 变量实际使用率 | 全文 `var(--fs-*)` 仅 **13 处**；硬编码 `font-size: Npx` 达 **135 处** | 全文检索统计（如 `:1048-1055`、`:1377`、`:2966-2979` 等均为硬编码 px） |
| root font-size 方案 | 对 px **完全无效**（px 是绝对单位），必须把 135 处改 rem/em 或包一层缩放变量 | CSS 单位语义 |
| `zoom`/`transform: scale` 替代 | 破坏 sticky 表头（`:1017-1018`）、滚动容器（`style.css:1013`）、4px 网格与弹层定位；且 Element Plus 组件自带字号不受 root 变量控制 | 同上 + `AGENTS.md §4.2-6` |
| 验证条件 | 本机浏览器自动化不可用，视觉回归只能 `npm run build` + 静态检查 | `AGENTS.md §6` |

**裁决**：X-A01 是「设计令牌体系改造 + 全量视觉回归」，工作量 M（≈1 周）且验证受限，**明确不算小功能，移出本次批次单独立项**。若用户仍想快速给年长用户价值，可做**局部降级**：只放大答案正文与结果表两处（改 2~3 个选择器，标为「大字号模式」而非「三档全局缩放」），并明确覆盖范围有限——这个降级版才是 XS/S 档。
