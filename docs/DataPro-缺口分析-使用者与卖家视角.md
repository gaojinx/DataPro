## 1. 视角与口径说明

### 1.1 两个视角的定义

| 视角 | 定义 | 关注核心 |
|---|---|---|
| **具体使用者（User）** | 每天真正用 DataPro 的人。覆盖三类：① 业务人员（问数看数）；② 数据分析师（复杂取数/导出/深度分析）；③ 管理员（配权限/口径/巡检/看板） | 「用得顺不顺、敢不敢信、要不要反复找人」 |
| **卖家（Seller）** | 把 DataPro 当作产品对外销售/交付的一方（供应商/产品负责人） | 「能不能卖、能不能交付、能不能 Scale」——卖点包装、演示/试用、多租户隔离、计费配额、交付自动化、SLA、品牌定制 |

> 补充：数仓为电商场景（`dwd_shop`），店铺卖家/商家这一业务角色带来的独有缺口（多店铺数据隔离、经营看板）在 §2 中少量纳入使用者视角，但不喧宾夺主。

### 1.2 本次分析边界

- **只写当前确实缺的内容**。每条结论先核对功能清单与前端源码，已实现的（如 F13 图表、F30 依据折叠、F11 导出审批、B12 鉴权、A11 自动学习）**不再列为缺口**。
- **严格区分四种性质**，这是本次分析的价值所在：
  - `补入口` = 后端接口/能力已就绪，前端缺操作页或按钮；
  - `补文档` = 能力已实现，但手册/帮助/交付文档没跟上；
  - `补配置/补数据` = 功能已就绪，但生产数据或账号配置未落地；
  - `增强` = 在已有功能上加能力；
  - `全新` = 真正不存在，需新增设计。
- **不重复已识别的落地缺口**。此前需求池/架构评审已覆盖的「安全签字、生产 50 表元数据、A02 默认继承、时间窗锚点错、G4 证据、口径裁决/会话回收前端入口、Rerank/Milvus、Grafana/Langfuse 看板、7 份文档 v0.1、容器化未实跑」在 §1.3 统一归类、**不展开复述**；本文聚焦向前看的新缺口。
- 编号规则：`U-F` = 使用者·前端，`U-B` = 使用者·后端，`S-F` = 卖家·前端，`S-B` = 卖家·后端（与功能清单 F/B/A/D/S/E/I 编号体系区分）。

### 1.3 已知落地缺口的归类（不展开，衔接前序产出）

| 已知缺口 | 归类性质 | 本文处理 |
|---|---|---|

## 4. 缺口优先级矩阵

> 定级：**P0**=不补就卖不了/用不了；**P1**=影响体验与成交；**P2**=锦上添花。
> 性质缩写：全新 / 补入口 / 补文档 / 补配置 / 补数据 / 增强 / 补验证 / 补部署。

| 优先级 | ID | 视角 | 端 | 性质 | 现有功能编号（如有） | 一句话价值 |
|---|---|---|---|---|---|---|

## 5. 关键提醒（最容易被忽视但对「卖出去」致命）

1. **没有多租户/租户级隔离（S-B01），DataPro 只能卖给一家客户。** 当前全系统单租户、A02 是「用户→表」而非「用户→租户」，metadata/知识/审计/文件全无 `tenant_id`。这是 SaaS 化地基，架构评审已明确「行级隔离另立项目」——若对外销售，必须从now 把 tenant 维度贯穿设计，否则后期改造成本极高。

2. **没有 onboarding（U-F01）与追问建议（U-F07），再强的取数能力用户也用不起来。** 首页只有 4 张静态示例卡，手册里的「黄金公式」前端完全没露出；用户第一问就是「销售额多少」→ 被澄清 → 放弃。灰度准出要求「👎率<20%、正确率抽检≥90%」，差的不是模型，是引导。

3. **数据新鲜度不透明（U-F05/U-B01）是信任与合规的双重炸弹。** 默认窗口锚点 `today-1` 与真实分区不一致（AGENTS §6 明确记载），结果卡又不标数据截止日——用户会把「最近 7 天」的旧数据当成最新业务结论。这违反章程「宁可说不确定，绝不返回看似正确的错误数据」，比「没数据」更危险。

4. **演示/试用链路不通（S-F01），销售现场无法证明能力。** 站外产品页是纯静态站点，体验区内置示例不请求任何后端；潜在客户看到的只是「演示动画」，真实取数要本地起服务。成交转化的最后一公里断在这里。

5. **没有计量计费与套餐（S-B02/S-F05），卖出去也收不了钱、算不清成本。** 限流只按「用户/分钟」固定窗口，无租户配额、无调用计量、无账单。商业化闭环缺失会让产品停留在「内部降本工具」，无法成为可售商品。
