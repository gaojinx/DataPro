## 4. 建议新增功能（需求池）

> 类型标注：**增强**=在已有功能上加能力；**补入口/补配置/补文档/补验证**=已有能力缺落地动作，**不重复造轮子**；**新增**=全新功能。

### P0（必须上线前完成）

**P0-1｜安全评审与数据出域合规定稿**　`补评审 / 补文档`
- 用户故事：作为项目负责人，我希望安全与业务双方对身份透传、脱敏规则和 LLM 出域给出书面结论，以便 G1 门禁通过、灰度合法启动。
- 价值：消除一票否决风险；决定是否需要私有化模型替换。
- 验收标准：① 权限设计 §5 五项待确认项全部有结论并签字（身份透传 A/B 选型、脱敏规则 v1、L3 字段清单、审计保留时长、水印组件）；② DeepSeek 处理真实业务数据是否合规有书面裁决；③ 若判定不允许出域，私有化模型选型与预算单独立项。
- 依赖/前置：安全团队 + 业务接口人；架构师配合评估替换成本。
- 优先级理由：权限设计 §5 明示 G1 一票否决；章程 §10 列 LLM 部署方式为待确认。

**P0-2｜生产元数据 50 表实填与口径确认**　`补数据 / D02 增强`
- 用户故事：作为业务用户，我希望问到生产真实表和口径时有准确定义，以便不再得到「未收录」或错误答案。
- 价值：让召回与口径问答真正可用，防止种子回退造成幻觉。
- 验收标准：① 生产 50 表按《元数据与口径库模板》填报完成；② `import_metadata --dry-run` 零错误后正式入库；③ 抽检 20 条元数据/口径问答全部命中生产条目，无种子回退；④ 导入后重跑召回评测，表命中/口径命中不低于现有 97.5%/92%。
- 依赖/前置：业务方填报 + 数据工程导入；P0-1 的 L3 字段范围结论。
- 优先级理由：AGENTS.md §7 明确 P0；章程 §5 前置依赖「核心库 ≥50 表」。

**P0-3｜用户级表权限收紧与上线账号整治**　`补配置 / A02、B12 已有`
- 用户故事：作为管理员，我希望每个账号只看到岗位所需的表，以便不越权、审计可归因。
- 价值：把已实现的 A02 从「演示默认」变成生产有效；消除弱口令。
- 验收标准：① 所有非管理员账号表权限均非「继承全部」；② 越权表查询 100% E003 并有 `audit_log`；③ 演示账号改密、替换 `AUTH_SECRET`、清理测试Token；④ 导出审批重跑仍按申请人当前权限复核通过（AGENTS.md §4.1）。
- 依赖/前置：P0-1 权限方案结论、P0-2 元数据（勾选表来源）。
- 优先级理由：AGENTS.md §7(P0) + §6 演示账号风险；安全门禁不过则不得灰度。

**P0-4｜默认时间窗改读真实分区**　`增强 / F50、A04`
- 用户故事：作为业务用户，我希望「最近 7 天」真的落到有数据的时间段，以便不会把「没数据」误读成「业务 0 单」。
- 价值：修掉静默错误答案；让自检提示与 F50 探针口径一致。
- 验收标准：① 默认窗口末端与 F50 `MAX(dt)` 一致；② 构造分区落后 2 天场景，默认查询与 0 单自检均提示真实最新分区；③ 相对时间评测用例（`volatile`）不因该改动产生新的固定日期误判。
- 依赖/前置：架构师确认读取时机（启动/定时）与缓存策略；建议复用 `data_boundary` 探针。
- 优先级理由：AGENTS.md §7(P2) 列为日期来源缺口，但 §6 明确指出会导致错误结论，属 correctness 问题，提到 P0 止血。

**P0-5｜上线门禁验证包（L1~L5 + G4 清单）**　`补验证 / 补文档`
- 用户故事：作为 PM，我希望在灰度前有完整的门禁证据，以便对是否放量做有依据的决策。
- 价值：把「50/50 种子通过」升级为可审计的上线证据链。
- 验收标准：① 测试方案 §5 清单逐项勾选并附报告路径；② S1~S10 逐条通过记录（含 S9 数据夹带指令、S10 超长输入）；③ 并发 50 会话 P90 ≤30s、Milvus P95 ≤500ms；④ 评测指标达章程 §2.2 全部门槛；⑤ Runbook 告警通道与一键停服各演练 1 次；⑥ CI workflow 在 Linux 环境实跑一次。
- 依赖/前置：克隆库压测环境、CI runner、有 Docker 的机器（可先用 mock 替代 Milvus 项）。
- 优先级理由：测试方案 §5 是 G4 准入清单，当前全未勾选。

### P1（上线后一个迭代内）

**P1-1｜口径裁决管理与会话回收前端入口**　`补入口 / D03、S07`
- 用户故事：作为管理员，我希望在设置页直接裁决歧义口径并手动回收过期会话，以便不用手工调 API。
- 价值：零新后端开发，补齐管理闭环；灰度期可快速处理口径冲突。
- 验收标准：① 设置页可对歧义词新增/查看/删除默认口径裁决，保存后歧义问法直接采用且在「依据」声明；② 会话回收按钮可手动触发并展示清理结果（DROP TABLE/USER 数）；③ 两个入口仅管理员可见，接口仍按权限点校验。
- 依赖/前置：无（后端 `/admin/calibers/rulings`、`/admin/sessions/sweep` 已就绪）。
- 优先级理由：AGENTS.md §7(P2) 明确「前端入口缺口」，但接口已具备，性价比最高。

**P1-2｜Rerank 精排 + Milvus 实部署与 50+ 表评测**　`增强 / A05`
- 用户故事：作为业务用户，我希望表很多时也能召回正确的表与口径，以便取数结果可信。
- 价值：直接支撑幻觉率 ≤2% 门禁（章程 §2.2）。
- 验收标准：① Milvus 实跑连通，`VECTOR_BACKEND=milvus` 切换成功；② Rerank 接入后 Top-K 命中相对当前基线有可测提升（先固化基线报告）；③ 50+ 表规模评测表命中 ≥95%、口径 ≥90%；④ 停 Milvus 自动降级关键词召回，功能可用（`recall_degraded=true`）。
- 依赖/前置：有 Docker 的环境；Embedding/Rerank 本地部署需符合 P0-1 出域结论（章程 §4.1 要求本地部署）。
- 优先级理由：AGENTS.md §7(P1)、功能清单 A05 🔨；当前 11 表规模的高命中不能外推到生产 50 表。

**P1-3｜灰度监控看板与告警通道落地**　`补文档 / 补部署 / I03、I04、F48`
- 用户故事：作为值班人员，我希望每天能看到拒答率、👎率、错误率趋势，以便异常时及时止损。
- 价值：把灰度方案 §3 从纸面变成可执行机制。
- 验收标准：① Grafana 看板含 QPS/时延分位/节点失败率/token；② 业务看板含可执行率/拒答率/👎率日趋势；③ `alerts.yml` 四条规则 + 巡检失败规则可触发并演练 1 次；④ Langfuse 启用需通过合规确认，否则明确以本地 trace + `/trace` 标记码（F41）替代并写入 Runbook。
- 依赖/前置：部署侧 Grafana/Loki 资源；P0-1 的「上报内容含问题与 SQL」合规结论。
- 优先级理由：灰度方案 §2/§3 要求每日站会与看板；O-1/O-2 风险直接对应。

**P1-4｜治理文档定稿与追溯一致性治理**　`补文档 / 补核查`

- 价值：消除 C-1/C-2 风险，建立单一事实源。

- 依赖/前置：架构师核查实现现状。
- 优先级理由：章程 §9 要求 Gate 三方评审、书面变更；当前文档骨架无法支撑。

**P1-5｜评测集扩真实分布与 golden 持续积累**　`增强 / E03、F46`

- 价值：让「结果正确率 ≥90%」可被真实验证。

- 依赖/前置：灰度启动（P0-5 通过后）、业务接口人复核。
- 优先级理由：Q-1 风险；章程 §2.2 正确率门禁与 §5 评测前置依赖。
